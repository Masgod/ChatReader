# Release 0.5.0: Simpler Setup Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new streamer gets ChatReader working in OBS with one URL, sees only the settings they need, and learns when a new version is out.

**Architecture:** No new dependency, no change to the audio protocol. (1) A new page `/stream` loads the existing audio player and the existing bubble overlay together; `/overlay` and `/chat-overlay` keep working. (2) Settings sections get a Basic/Advanced split, chosen per device like the Touch/Mouse switch. (3) A background check asks GitHub for the latest release once at startup and once a day; a newer version shows a tray notification, a tray menu item and a banner in Settings.

**Tech Stack:** Python 3.11+/uv, FastAPI, pystray, plain JS, pytest (`uv run pytest -q -m "not slow"`).

**Base:** branch `feat/0.5`, cut from `feat/voice-quality` (0.4.0 work, not released yet).

## Global Constraints

- Integration branch: `feat/0.5` (worktree `.claude/worktrees/v0.5`). One branch per task (`v05/task-N-<slug>`) off it, merged back after the Arquiteto reviews the diff. Push to these branches is fine; push to `main`, tag or release only with the owner's explicit yes.
- Old OBS setups must keep working: `/overlay` and `/chat-overlay` stay, with the same behaviour.
- The update check is the app's only call home: one GET to `https://api.github.com/repos/Masgod/ChatReader/releases/latest`, no data sent, can be turned off (`check_updates`), and any failure is silent (log at debug only).
- Every behaviour change starts with a failing test. UI changes are also checked by screenshot at 715×384 and 425×580.

## Review Focus

- `/stream` open together with an old `/overlay` source: only one may own the audio (today the newest connection wins); the guide must say to delete the old sources.
- `/stream` must not double-play: the audio script is loaded once, not once per bubble or per reconnect.
- Basic view: a setting that is required for the app to work (chat source, voice) must never be hidden; the Getting started checklist still shows.
- Update check: a tag like `v0.10.0` is newer than `v0.9.0` (compare numbers, not strings); a pre-release or draft is ignored; rate-limit (403) or no network never raises; the same version is announced once per run, not every day.
- The version shown and compared must come from one place that also matches `pyproject.toml` (a test asserts it).
